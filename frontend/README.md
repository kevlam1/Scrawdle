# frontend

- `index.html`: the home screen, reveal screen, and parts above the canvas.
- `prompts.json`: the parts the slot machine picks from.
- `daily.js`: picks the same parts for everyone on a given date.
- `drawing.js`: the drawing tools, brush types, undo and redo, auto-save, replay, and the finish screen.
- `leaderboard/index.html`, `leaderboard.js` and `leaderboard.css`: Today's leaderboard, served at `/leaderboard/` (linked from the home screen, the finish screen, and Public drawings). It loads today's drawings through `publish.js`'s `scrawdlePublicGallery`, the same as Public drawings, and ranks them by thumbs up. Daily Scrawl's list is locked until the player has posted one (`scrawdleHasPosted`). `leaderboard.js` also draws "Yesterday's winners" (`yesterdaySection`), on the leaderboard and, compact, on the home screen, from `publish.js`'s `scrawdleYesterdayWinners` (database update `005`). The ranking and the winner wording are tested in `../tests/leaderboard.test.js`, and the loader in `../tests/yesterday-winners.test.js`.
- `streak.js`: the streak of days in a row with a finished daily drawing. `drawing.js`'s finish screen records the day and shows the line, `index.html`'s home screen shows it under the date, and the share text ends with it. Kept in `localStorage` (`scrawdle-streak`), so it's per browser. Load it before `drawing.js`. Its date math is tested in `../tests/streak.test.js`.
- `color-picker.js` and `color-picker.css`: Scrawdle's own color picker, opened from the rainbow "Custom" button in the tool tray, so it looks the same in every browser instead of using the browser's built-in one. `drawing.js` makes one per board. Load `color-picker.js` before `drawing.js`. Its color math is tested in `../tests/color-picker.test.js`.
- `drawing.css`, `studio.css`, and `flow.css`: the look of the game, loaded in that order. Later files override earlier ones.
- `fonts/`: Patrick Hand and Gochi Hand.
- `assets/tools/`: the illustrated icons for the drawing tools.
- `gallery.js`: today's gallery (a dialog over the finish screen), with thumbs up/down buttons and a Report button on other players' drawings, and your result on your own. It also draws the Public drawings page: `createGallery(null, { container })` puts it in a page instead of a dialog.
- `public-drawings/index.html`: the Public drawings page, served at `/public-drawings/` (the home screen links to it, and so does the finish screen, with `?focus=daily` or `?focus=free` to start on one kind). It loads the same stylesheets as the home screen, `votes.js`, `gallery.js`, and Supabase's client with `publish.js`, then calls `showPublic`. Its paths start with `../`, so they work with or without the trailing slash. It shows only today's drawings by the viewer's local date.
- `votes.js`: the vote rules, including the win condition (one thumbs up wins). Change the rule here; no database update needed. Tested in `../tests/votes.test.js`.
- `sketchbook.js` and `sketchbook.css`: My drawings, the player's own drawings kept in this browser.
- `supabase-config.js`: the Supabase project URL and anon key. Filled in with Kevin's real project; safe to commit (the key is meant to be public, see `../CLAUDE.md`). Running the page locally publishes to that same real project.
- `publish.js`: wires `window.scrawdlePublish`, `window.scrawdleGallery`, and `window.scrawdleVote` to Supabase (votes need `../backend/supabase/updates/002-votes.sql`). Tested against a stand-in for Supabase in `../tests/publish-votes.test.js`. Does nothing until `supabase-config.js` has real values, so the Publish button and gallery stay hidden exactly as before.
- `lobby.js` and `lobby.css`: lobbies, joined with an invite link like `/?BCDFG` (players never see or type the code in it): the Lobby card on the home screen, the lobby room, and the contract games plug into (`ScrawdleLobby.registerGame`). Read the comment at the top of `lobby.js` before building a multiplayer game, and the "Lobbies and adding a multiplayer game" section of `../CLAUDE.md`. Does nothing if `supabase-config.js` is empty. Its pure logic is tested in `../tests/lobby.test.js`.
- `party.js`, `party-rules.js` and `party.css`: Scrawdle Party, the first lobby game. `party.js` is the screens and the lobby messages (the list of messages is at the top of the file); `party-rules.js` is the scoring, winners, and settings, tested in `../tests/party-rules.test.js`. It reuses the drawing board from `drawing.js` with `idPrefix: "party-"`, and never gives it a round, so it can't save over a player's drafts.
- `logs/index.html`: the build-log page, served at `/logs`. **Generated** from `../log.md`, `../scripts/log-summaries.mjs`, and `../scripts/logs-template.html` by `node scripts/make-logs-page.mjs`; edit those, not this file. The game links to it from the bottom of the home screen ("Read our build log").
- Daily Free Play (a card on the home screen; internal id `scrawl`, kept so the database and saved drawings don't change) is a free-draw mode with no parts. It is a normal round with mode `scrawl` and one pseudo-prompt, "Draw anything", so the prompt bar, finish screen, PNG export, and gallery work unchanged. It has its own save slot in `drawing.js` (cleared each day, like Basic and Detailed). Its drawings get votes like the others; with no parts, a thumbs up just means another player liked it.

Publishing needs `supabase-config.js` filled in and the schema in `../backend/supabase/schema.sql` run against a real project; both are done. With the two config values emptied, the page works without publishing — see the comments at the top of `drawing.js` and `gallery.js` for the hooks.

Stack is proposed in `../CLAUDE.md`, not locked: plain HTML5 Canvas with vanilla JS/TS, no UI framework. Replace or restructure this folder once the team confirms that and splits up ownership.
